### <a id="microsoft-hydrafusion"></a>[未掲載] Microsoft (GitHub Copilot): Project HydraFusion — マルチモデルオーケストレーション研究プレビュー (9/4)

GitHub が 9 月 4 日、**Project HydraFusion** を GitHub Copilot CLI 向け研究プレビューとして公開した。[9/4 サマリー](summaries/2026/09/2026-09-04.md) では Microsoft の発表なしと記載したが、本発表はその後に確認されたため本日掲載する。

**仕組み**: タスクごとに最適なモデル・実行パターンを動的に選択するオーケストレーション層。3 つの実行パターンを持つ:
- **Single** — 1 つのモデルが直接タスクを解く
- **Cascade** — 効率的なモデルが下書きし、品質基準を満たさない場合は上位モデルにエスカレート
- **Critique** — 1 モデルが解答を生成し、別モデルファミリーの独立したレビュアーが評価後に修正

**ベンチマーク結果** (Claude Opus 5 比):
- TerminalBench 2.1: **品質 +4.9pp、コスト -67%**
- DeepSWE: 品質 -1.5pp 以内、コスト **-36%**
- CheckpointBench: 品質 -0.1pp 以内、コスト **-65%**

**利用方法**: GitHub Copilot 全プランのユーザーが Copilot CLI で `/experimental on` を設定後、`/model` で "HydraFusion (Research Preview)" を選択。課金は使用した各モデルの標準レートに準じる。

なぜ重要か: 単一モデルのスケールアップではなく「複数モデルの動的組み合わせ」でフロンティア品質を実現するアプローチは、コスト競争力の観点から重要な設計転換を示す。Anthropic Claude Opus 5 と比較して品質をほぼ維持しながら 36〜67% のコスト削減を達成したことで、エンタープライズ向け展開での経済合理性が大幅に向上する。

- 公式ブログ: [Project HydraFusion: Frontier quality via multi-model orchestration — GitHub Blog (9/4)](https://github.blog/ai-and-ml/github-copilot/project-hydrafusion-frontier-quality-via-multi-model-orchestration/)
- 詳報: [GitHub Introduces Project HydraFusion: Runtime Multi-Model Orchestration — MarkTechPost (9/5)](https://www.marktechpost.com/2026/09/05/github-introduces-project-hydrafusion-runtime-multi-model-orchestration-that-builds-a-workflow-per-coding-task-in-copilot-cli/)
