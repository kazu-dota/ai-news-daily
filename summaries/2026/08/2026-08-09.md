### <a id="anthropic-mid-conv-tools"></a>[新] Anthropic: ミッドコンバセーション・ツール変更ベータ (Claude Fable 5 / Mythos 5 / Opus 4.8 / Opus 5)

Claude API で、会話の途中でツールセットを変更できる **ミッドコンバセーション・ツール変更** ベータが公開された。`tool_addition` / `tool_removal` content block を `role: "system"` メッセージに含めることで、トップレベルの `tools` 配列を再送信せずにツールを追加・削除できる設計だ。

**主な仕様**:
- ベータヘッダー: `mid-conversation-tool-changes-2026-07-01`
- 対応モデル: Claude Fable 5、Claude Mythos 5、Claude Opus 4.8、Claude Opus 5
- 従来のミッドコンバセーション・システムメッセージ機能のツール版として位置づけ

なぜ重要か: エージェントがタスクの進行中に使えるツールを動的に切り替えられるようになる。これまでは `tools` 配列を変更するとプロンプトキャッシュが無効化されてしまうため、ツールセットを固定せざるを得なかった。本ベータにより、会話の文脈に応じてツールを出し入れしながらもキャッシュコストを維持できるロングランエージェントの設計が可能になる。

### <a id="microsoft-unified-copilot"></a>[新] Microsoft: 統合 Copilot アプリ — GitHub Copilot・Chat・Cowork・AutoPilot を 1 本化 (8/2026)

7 月初旬の社内メモで示されていた Microsoft Copilot の「スーパーアプリ化」が 8 月、CSP (Cloud Solution Provider) 経由の提供として現実化した。

**統合内容**:
- 従来バラバラだった GitHub Copilot (コーディング)・Copilot Chat (チャット)・Copilot Cowork (コラボレーション) を 1 つのアプリに統合し、共通の ID グラフで結ぶ
- 新エージェント層 **AutoPilot** を追加: Teams・Outlook・OneDrive・SharePoint のシグナルを監視し、あらかじめ設定したトリガー条件が満たされると自律的にアクションを実行 (ユーザーのプロンプトを待たない設計)
- **廃止**: Copilot Podcasts (自動生成音声サマリー) と Copilot Labs (実験的機能チャンネル) — 利用率が低く、フォーカスを絞る判断

なぜ重要か: M365 Copilot の有料転換率がいまだ商用シート全体の 4.5% 未満という状況で、ブランド分散を解消して採用率の底上げを狙う。AutoPilot が「指示を待って反応する」ではなく「条件を監視して先に動く」設計であることは、職場における AI エージェントの役割が指示反応型から能動的バックグラウンド型へ移行する次フェーズを象徴する。

### <a id="mistral-shieldstral"></a>[新] Mistral: Shieldstral 1.0 (3B) — オープンウェイト多言語マルチモーダル安全分類器 (8/7)

8 月 7 日、Mistral AI が **Shieldstral 1.0** を公開した。テキストと画像を同一モデルで評価し、推論時に平易な言語で記述したポリシーを適用できる 3B パラメータのオープンウェイト安全分類器だ。

**主な仕様**:
- アーキテクチャ: Ministral-3-3B-Base-2512 + Pixtral ビジョンエンコーダ
- 対応言語: **12 言語**、対応入力: テキスト + 画像 (マルチモーダル)
- ハードウェア要件: 16GB GPU 1 枚、CPU のみでも動作可
- ライセンス: **Apache 2.0**
- 学習データ: 5,410 万の対比ポリシーペア

**ベンチマーク**:
- HarmBench: **99.4%**
- VLGuard (ビジョン安全): **97.7%**
- 7 倍大きいモデルに匹敵するパフォーマンス (同社報告)

**設計の核心**: 固定ラベルセットを学習で焼き付けるのではなく、「ポリシーの対比ペア」を用いて似た・異なるルール間の識別を学習させる。これにより推論時に新しいポリシー文を入力するだけで分類基準を動的に変更可能で、再学習なしにポリシーを入れ替えられる。

なぜ重要か: コンテンツモデレーションを「外部 API 依存」から「インハウス」に移行したい企業にとって、Apache 2.0・単一 GPU 動作・3B という組み合わせは実用的な閾値を下げる。金融・医療・法務など、データを外部 API に送信できないコンプライアンス環境での採用が見込まれる。
